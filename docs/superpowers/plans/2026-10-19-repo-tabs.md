# Repository Tabs Implementation Plan

## สรุปแผน (อ่านส่วนนี้ส่วนเดียวก็เข้าใจว่าจะทำอะไร)

### ปัญหาที่เจอ

เพื่อนของผู้ใช้ทำงานกับหลาย repo พร้อมกัน แต่ใน GitKrapao การเปลี่ยน repo ทุกครั้งต้องกดปุ่ม Repository บน toolbar ให้เมนู recent เด้งลงมาก่อน แล้วจึงเลือก repo ได้ จากนั้นแอปจะโหลด repo ใหม่ทั้งหมดและจำไม่ได้ว่าเคยเลือก commit ไหนไว้

นอกจากนี้ ตอนนี้แอปทำ fetch หรือ switch branch ได้ทีละงานทั้งแอป ถ้า fetch repo หนึ่งค้างอยู่นาน จะไปทำงานกับ repo อื่นไม่ได้เลย ปัญหานี้เกิดกับแอปเดสก์ท็อปบน Windows ทุกเครื่อง ไม่เกี่ยวกับ environment ใดเป็นพิเศษ

### แนวคิด

เพิ่มแถบแท็บแบบ GitKraken ไว้เหนือ toolbar หนึ่งแท็บคือหนึ่ง repo คลิกแท็บไหน แอปก็โหลดและแสดง repo นั้น แอปถือข้อมูลไว้ในหน่วยความจำแค่แท็บที่เปิดดูอยู่แท็บเดียว เพื่อไม่ให้กินทรัพยากรเครื่อง งาน fetch และ switch branch แยกกันตามแท็บ แต่ในแท็บเดียวกันยังทำได้ทีละงาน

เคสต่างๆ เป็นแบบนี้

- **สลับแท็บปกติ:** แอปโหลด repo ของแท็บนั้น ถ้า commit ที่เคยเลือกไว้อยู่ในส่วนที่โหลดมาแล้ว ก็เลือกให้อีกครั้ง ถ้าไม่อยู่ก็เริ่มดูจากด้านบน และจะไม่โหลดลึกลงไปเพื่อตามหา เพราะจะเปลืองเครื่อง
- **สลับแท็บระหว่างที่แท็บเดิมยังโหลดไม่เสร็จ:** แท็บที่กดทีหลังชนะ ผลของแท็บเก่าที่มาถึงทีหลังจะถูกทิ้ง ตอนนี้แอปจะเมินการกดนั้นไปเฉยๆ
- **กลับไปแท็บที่ fetch หรือ switch ยังไม่เสร็จ:** กลางจอขึ้นข้อความว่า "Fetching… the history loads when it finishes" แทนกราฟ พองานเสร็จแล้วยังอยู่แท็บนั้นอยู่ แอปจะโหลดให้เอง กราฟของแท็บอื่นจะไม่ค้างโชว์อยู่ใต้แท็บนี้
- **ระหว่างที่แท็บหนึ่งมี fetch หรือ switch ทำงานอยู่:** ในแท็บนั้นจะกด Fetch, Switch, Refresh, ซ่อนหรือแสดง branch, Solo, เลือก repo จากเมนู Repository และปิดแท็บไม่ได้ แต่ยังสลับไปแท็บอื่น เปิดแท็บใหม่ และเลื่อนดูกราฟได้
- **งานในแท็บที่ไม่ได้ดูอยู่เสร็จ:** ผลจะถูกบันทึกลงใน Output drawer โดยไม่เปิด drawer ขึ้นมาเอง และไม่ขึ้นแถบ error ทับแท็บที่ดูอยู่ ถ้างานล้มเหลว แท็บนั้นจะมีจุดแดงจนกว่าจะคลิกเข้าไปดู
- **ทำงานพร้อมกันเกิน 3 งานทั้งแอป:** ปุ่ม Fetch และ Switch จะจางลงพร้อมคำอธิบาย เหตุผลคือไม่ให้กินเครื่อง
- **ปิดแอปตอนยังมีงานค้าง:** ขึ้นหน้าต่างเตือนที่บอกว่ามีงานอะไรค้างอยู่ใน repo ไหน ให้เลือก Close anyway หรือ Cancel เพราะถ้า switch ถูกหยุดกลางทาง ไฟล์ใน work tree อาจอัปเดตไปแค่ครึ่งเดียว ถ้าไม่มีงานค้างก็ปิดได้ทันทีเหมือนเดิม
- **repo ของแท็บหายไปหรือเปิดไม่ได้:** แท็บแสดง error และหน้าว่างที่มีรายการ recent แท็บยังอยู่ในแถบให้กดปิดเองได้

### ฝั่ง BE (Rust, src-tauri)

- **ตัวเก็บรายการงานที่กำลังทำ:** ตอนนี้แอปจำ PID ของงาน fetch หรือ switch ได้ตัวเดียว (`op_pid`) จะเปลี่ยนเป็นตัวเก็บต่อ repo ที่บันทึกชนิดงาน ชื่อ repo และ PID ไว้ เวลาปิดแอปจะได้หยุดงานได้ทุกตัว และใช้แสดงรายการในหน้าต่างเตือนตอนปิดแอปได้ด้วย
- **หัวหน้าต่าง trust และ Stash and switch:** ใส่ชื่อ repo ลงไปด้วย กันเพื่อนเผลอกดยืนยันให้ผิด repo เพราะหน้าต่างของ repo A อาจเด้งขึ้นตอนกำลังดูแท็บ B
- **`RepoInfo`:** เพิ่ม field `lockKey` ฝั่ง UI จะได้รู้ว่า worktree หลายอันของ repo เดียวกันใช้ล็อกร่วมกัน
- **ส่วนที่ไม่ต้องแก้:** การโหลด history ไม่ต้องแก้ เพราะ `start_history` รันได้ทีละสตรีมและ kill สตรีมเก่าเองอยู่แล้ว ([lib.rs:585](src-tauri/src/lib.rs#L585)) ล็อกต่อ repo (`busy_repos`) ก็แยกตาม repo อยู่แล้ว

### ฝั่ง UI (TypeScript, src)

- **ไฟล์ใหม่ `src/tabs.ts`:** เก็บรายการแท็บ บันทึกลง localStorage ที่คีย์ใหม่ `lanes.tabs` และย้ายข้อมูลจาก `lanes.last` ให้ครั้งแรกที่เปิดแอป
- **แถบแท็บใน `index.html` / `app.css`:**
  - ปุ่ม + มุมขวาสุด
  - ปุ่ม ⌄ เปิดรายการแท็บทั้งหมด
  - วงหมุนบนแท็บที่มีงานทำอยู่
  - จุดแดงบนแท็บที่งานล้มเหลว
- **คีย์ลัด:**
  - Ctrl+T เปิดแท็บใหม่
  - Ctrl+W ปิดแท็บ
  - Ctrl+Tab สลับแท็บ
  - Ctrl+1 ถึง 9 ไปแท็บตามลำดับ
- **`loadRepo`:** เพิ่มเลขลำดับการโหลด ให้การโหลดล่าสุดชนะ
- **รายการ PR:** จำแยกตาม repo ไว้ 5 นาที สลับแท็บไปมาจะได้ไม่เรียก `az` ใหม่ทุกครั้ง
- **สถานะงาน fetch/switch:** เปลี่ยนจากตัวแปรเดียวทั้งแอป (`opPath`) เป็น `Map` ต่อ repo

### ผลกระทบ

- **repo อื่น:** ไม่มี repo อื่นเรียกใช้ GitKrapao
- **ผู้ใช้เวอร์ชันเก่า:** ครั้งแรกที่เปิดเวอร์ชันใหม่ repo ล่าสุด (`lanes.last`) จะกลายเป็นแท็บแรก ค่าที่บันทึกไว้ (`lanes.*`) อยู่ครบ แอปยังเขียน `lanes.last` ต่อ ถ้าถอยกลับไปเวอร์ชันเก่าก็ยังเปิด repo ล่าสุดได้
- **DB / config / secret:** ไม่มีการเปลี่ยน
- **สิ่งที่ผู้ใช้จะเห็นเปลี่ยนไป:**
  - มีแถบแท็บสูงราว 30px เพิ่มเหนือ toolbar
  - เมนู Repository เปลี่ยน repo ในแท็บปัจจุบัน
  - ระหว่าง fetch หรือ switch ในแท็บหนึ่ง ปุ่ม Refresh, ซ่อน branch และ Solo ของแท็บนั้นจะจางลง ตอนนี้กดได้แต่แอปจะรอให้งานเสร็จก่อน
  - ปิดแอประหว่างมีงานค้างจะเจอหน้าต่างเตือน
- **Security / PDPA:** หน้าต่าง trust แสดงชื่อ repo ซึ่งปลอดภัยขึ้น ไม่มีข้อมูลส่วนตัวใหม่ถูกเก็บ `lanes.tabs` เก็บแค่ path กับชื่อ repo เหมือน `lanes.recent`
- **ข้อจำกัดที่ยังเหลือ:**
  - สลับแท็บแล้วยังต้องรอโหลด ไม่ทันทีแบบ GitKraken
  - ไม่มี auto-fetch
  - ลากเรียงแท็บไม่ได้
  - การเรียก `az` หรือ `git for-each-ref` ที่ค้างจากแท็บที่เพิ่งออกมาจะไม่ถูกยกเลิก ปล่อยให้จบเองแล้วทิ้งผล

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a GitKraken-style tab strip, one tab per repository, with fetch/switch independent per tab and nothing running for background tabs.

**Architecture:**
- **One repo at a time.** The app still holds one repository in memory (the active tab). Activating a tab runs the existing `loadRepo`, made supersedable by a load token.
- **Tab state.** The tab list and its persistence live in a new `src/tabs.ts`.
- **Per-repo actions.** The app-wide `opPath`/`opKind`/`pendingLoad`/`opErr` become per-repo state keyed by a new `RepoInfo.lockKey`.
- **Rust.** `busy_repos` becomes a registry of running operations (kind, repo name, PID slot), which gives the exit path all PIDs and the close warning its list.

**Tech Stack:** Tauri 2 (Rust), TypeScript bundled by esbuild, UI tests in headless Edge with a fake `__TAURI__` (`tests/ui/*.suite.mjs`).

**Spec:** `docs/superpowers/specs/2026-10-19-repo-tabs-design.md`

## Context

- **How switching repos works today:**
  - Repos are switched through `#repoBtn` → `#recentMenu` (`src/app.ts:2443`). It calls `openPath` → `open_repo` → `loadRepo` (`app.ts:2160`).
  - `loadRepo` returns early while `busy` (`app.ts:2161`).
- **Operations:**
  - `runOp` (`app.ts:2356`) allows one fetch/switch app-wide through `opPath`.
  - The backend `RepoLock` (`fetch.rs:84`) is already per `lock_key`. `AppState.op_pid` (`lib.rs:183`) holds one PID, which the exit handler kills (`lib.rs:1464–1472`).
  - `ask_native` titles (`fetch.rs:605`, `switch.rs:329–330`) don't name the repo.
- **Async loaders already guard on path/seq:**
  - `loadTracking` (`app.ts:1371`), `loadWip` (`1572`), `loadStashes` (`1680`), `loadPrs` (`1835`), `loadRemotes` (`2346`);
  - `requestDetail` and the diff cache, keyed by repo path (`824`, `962`).
  - `loadPrs` resets the single `prs` when the path changes (`1828`), so every switch would re-run `az`.

## Global Constraints

- **localStorage keys:** keep every existing `lanes.*` key and the Tauri identifier `local.lanes.gitgraph`. The new key is `lanes.tabs`.
- **Fetch stays manual only.** No background fetch.
- **Commands:**
  - fetch: `git fetch --all --prune --no-prune-tags --no-auto-maintenance --no-recurse-submodules`, never `-c core.sshCommand`/`credential.helper` overrides;
  - switch: never `--force` / `--discard-changes` / `--merge`.
- **Background tabs do no work:**
  - no poll, no `work_status`, no `pull_requests`, no `branch_tracking`, no `list_stashes`;
  - no history stream.
- **Concurrency cap:** at most **3** fetch/switch operations running app-wide.
- **New CSS classes start with `tab-` / `tabs-`.** Never reuse graph class names (`.head`, `.row`, …).
- **TypeScript rules:**
  - `strict` + `noUncheckedIndexedAccess`;
  - no `@ts-ignore`, no `any` except at a parse boundary with a comment;
  - every `!`/`as` carries its reason.
- **Bindings:** a changed Rust struct sent to the UI → `cargo test --lib` regenerates `src/bindings/*.ts`; commit them.
- **Test data:** tests and manual checks use fake `__TAURI__` data or mock repos only, never the user's work repos.
- **Copy (exact strings):**
  - New tab label: `New tab`
  - Placeholder while busy: `Fetching… the history loads when it finishes` / `Switching branch… the history loads when it finishes`
  - Cap tooltip: `3 fetches or switches are already running; wait for one to finish`
  - Close disabled tooltip: `Wait for the fetch or switch in this repository to finish`
  - Close-app dialog: title `GitKrapao: operations still running`, OK button `Close anyway`, Cancel `Cancel`
  - Dialog titles: `Fetch — <name>: trust this repository?`, `Switch branch — <name>: uncommitted changes`, `Switch branch — <name>: trust this repository?`

## Review Focus

1. **A late result from the tab the user just left lands in the new tab.** Tracking, stashes, WIP, PRs or commit detail must never appear under another tab. Covered by `tabs.suite` "late results from A are dropped" (Task 4).
2. **Clicking a tab during a slow load is ignored** (the old `busy` early return). Covered by `repo-switch.suite` "newest load wins" (Task 3).
3. **A fetch failure in a background tab** pops the banner or opens the drawer over the active tab. Covered by `tabs-ops.suite` "background failure is quiet" (Task 5).
4. **Two worktrees of one repo open as two tabs:** a fetch in one must show as running in the other, not fail later with "busy". Covered by `tabs-ops.suite` "shared lockKey" (Task 5).
5. **A saved tab whose folder was deleted:** restoring must not crash the boot, and the tab stays closable. Covered by `tabs.suite` "missing repo tab" (Task 4).
